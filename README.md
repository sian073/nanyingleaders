# 領隊公布欄 — 維護說明

2026 南瀛國際民俗藝術節
維護者：林頎姍（路米爾有限公司）

---

## 一、基本流程

不需要在電腦裡裝任何軟體，直接在 GitHub 網頁上改就好。

1. 進到你的 repo，點 `index.html`
2. 右上角鉛筆圖示（Edit this file）
3. 改完內容
4. 拉到下面按 **Commit changes**，說明欄寫一句像「更新接送機報帳規定」
5. 等一到兩分鐘，重新整理公布欄網頁，就是新的了

---

## 二、每次改完都要做的一件事

**把最上面的更新日期改掉。**

用 Ctrl+F（Mac 是 Cmd+F）搜尋 `LAST-UPDATED`，下一行就是：

```html
<span class="updated">最後更新：2026 年 9 月 1 日</span>
```

領隊是靠這個日期判斷資訊新不新的。忘了改，等於這次更新白做。

---

## 三、新增一則公告

複製下面這一整塊，貼到 `<h2>最新公告</h2>` 的**下一行**（愈新的公告放愈上面）。

```html
  <article class="notice">
    <p class="stamp">2026/09/10</p>
    <h3>公告標題 <span class="tag tag-ok">已確認</span></h3>
    <p>
      內容寫在這裡。
    </p>
  </article>
```

只有三個地方要動：

| 要改的 | 位置 |
|---|---|
| 日期 | `<p class="stamp">` 裡面 |
| 標題 | `<h3>` 裡面 |
| 內容 | `<p>` 和 `</p>` 中間 |

### 狀態標籤

| 想標成 | 就寫 |
|---|---|
| 已確認 | `<span class="tag tag-ok">已確認</span>` |
| 暫定 | `<span class="tag tag-tbc">暫定</span>` |

一則公告裡如果有些確定、有些還沒確定，可以在小標題後面單獨掛標籤，
不要整則掛同一個，會誤導人。

### 內容比較長的時候

多段文字就多寫幾組 `<p>...</p>`：

```html
    <p>
      第一段。
    </p>
    <p>
      第二段。
    </p>
```

要加小標題（橘紅色那種）：

```html
    <h4>小標題</h4>
```

要加條列：

```html
    <ul class="leg">
      <li>第一點</li>
      <li>第二點</li>
    </ul>
```

要特別強調的段落（橘色外框那種）：

```html
    <div class="callout">
      <p>要強調的內容。</p>
    </div>
```

要放連結：

```html
    <a href="https://網址">看起來的文字</a>
```

## 四、「還在確認中」的維護

問題還沒有答案時，加在那一區的清單裡：

```html
    <li>問題寫在這裡</li>
```

**問題有答案之後，要做兩件事：**

1. 把那一行 `<li>...</li>` 從清單裡刪掉
2. 在「最新公告」最上面新增一則公告，寫出答案

只做第一件事，領隊會以為問題消失了；只做第二件事，清單會累積過期問題。

## 五、改壞了怎麼辦

不會真的弄丟東西。GitHub 每次 commit 都留紀錄。

- 進 repo 點 **History**
- 找到上一個正常的版本
- 進去按 **Revert** 或直接複製舊內容貼回去

更保險的做法：改之前先按 **Download raw file** 存一份到桌面。
改壞了直接拿那份覆蓋回去。

## 六、最容易出錯的兩件事

**1. 標籤要成雙**

`<p>` 開頭就一定要有 `</p>` 結尾。
`<article ...>` 開頭就一定要有 `</article>` 結尾。
複製整塊來改，比自己從頭打安全很多。

**2. 中文裡不要出現落單的角括號**

想寫「機場 → 飯店」，用箭頭符號 `→`，不要用 `->` 或 `>`。
這幾個符號會被當成標籤的開頭，整頁排版就亂了。
真的要寫，用 `&lt;` 代表 `<`、`&gt;` 代表 `>`。

## 七、這是公開網頁

任何人拿到網址都看得到。**不要放：**

- 住宿地址、門牌
- 領隊名單、姓名
- 電話、身分證字號、任何個資
- 內部往來訊息、還沒對外定案的金額

需要提到這類資訊時，改寫成「請洽路米爾窗口」。

## 八、更新後的檢查清單

- [ ] 更新日期改了
- [ ] 新公告放在最上面
- [ ] 狀態標籤掛對了（已確認 / 暫定）
- [ ] 有答案的問題，從「還在確認中」移走了
- [ ] 用手機開一次，確認沒有跑版
- [ ] 重要更新另外發一封短信提醒（公布欄不會主動通知）
